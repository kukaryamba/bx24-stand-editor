# Ход работы

Файл для того, чтобы продолжить работу на другом компьютере или в новой сессии,
не восстанавливая контекст заново.

Обновлено 13 августа 2026 года по состоянию кода на коммит `6722624`.

## Задача

Приложение для планирования выставочных стендов работало в amoCRM. Нужно
перенести его в Битрикс24.

## Исходное состояние: три папки

Их передала коллега, все три остались на рабочем компьютере и **в репозиторий не
попали** — в них лежат ключи и логи с данными клиентов.

| Папка | Что это |
|---|---|
| `amo_crm` | React-редактор общего плана + копия старого PHP-приложения. Делался через Codex |
| `amo_crm 2` | то же старое приложение + начатый слой перехода на Битрикс24, другая нейросеть |
| `оригинал amo_crm старый` | оригинал с хостинга, без изменений |

Проверено: **фронтенд второй и третьей папок побайтово идентичен**. Реальных
версий продукта две — старая на PHP и новая на React.

## Почему старое приложение не вернуть

1. **API amoCRM не отвечает.** Запрос к `/private/api/v2/` возвращает 402 — и с
   ключом, и без него. Приложение построено на устаревшем API с авторизацией по
   логину и хэшу.
2. **Библиотека ломает ответы.** На PHP 8 `amocrm.phar` выдаёт полтора десятка
   сообщений `Deprecated` перед JSON, из-за чего браузер не может его разобрать.
3. **Хостинг отключают** — компания переезжает на Тильду. Всё, что на PHP,
   перестанет работать физически.

## Что решили

Делать новое приложение на React в папке `bx24_stand_editor` (этот репозиторий),
на основе редактора из папки `amo_crm`. Работать поэтапно.

## Сделанные этапы

Подготовка:

1. **Запуск.** Библиотеки в исходной папке были собраны под macOS — Vite не
   стартовал на Windows. Докачаны сборки `@rollup/rollup-win32-x64-msvc` и
   `@esbuild/win32-x64`.
2. **Разбор.** Сведено, что из ТЗ уже есть в старом приложении и в React-редакторе.

Два экрана:

3. **План стенда.** Второй экран: каталог 43 предметов, расстановка
   перетаскиванием, поворот, удаление, панель свойств.
4. **Разделение планов.** Общий план выставки и площадка стенда — теперь разные
   планы со своими размерами и своей сеткой. Экран не хранится отдельно, а
   определяется тем, какой план открыт.
5. **Связь карты со стендами.** У каждого стенда на карте выставки своя площадка,
   она заводится при первом открытии. В левой панели список всех стендов —
   можно переходить между ними, не возвращаясь на карту.

Работа с планом:

6. **Типовые схемы стендов** — расставляют стены по периметру (мебель остаётся
   на месте, прежние стены заменяются). Плюс кнопки типовых размеров: 3x3, 4x3,
   6x3, 6x4, 9x6.
7. **Спецификация** — перечень предметов на плане, сгруппированный по категориям,
   с площадью, периметром и длиной стеновых панелей. Повторяет логику старого
   `specification.php`. Есть выгрузка текстом, чтобы вставить в письмо.
   **Суммы не считаются**: цен нет ни у одной позиции, они лежат в каталоге
   портала. Пустые цены намеренно не заменяются нулями.
8. **Сохранение в PNG** — план целиком, а не видимая часть, с двойным разрешением.
9. **Управление холстом** — панорама нажатием колёсика мыши; перетаскивание
   объектов больше не сбивает вид.

Битрикс24:

10. **Сохранение в сделку.** Панель «Сделка» на экране плана стенда: сохранить и
    загрузить. План пишется в пользовательское поле сделки в виде JSON, поле
    приложение создаёт само при первом сохранении. Ищет своё поле по признаку
    `XML_ID = BX24_EXPO_STAND_PLAN`, а не по имени. Сервера у приложения нет,
    всё идёт из браузера через JS-библиотеку портала.

## Что дальше

Порядок по важности:

1. **Установка в портал** — собрать `dist`, выложить на статический хостинг с
   HTTPS, зарегистрировать локальное приложение (встраивание
   `CRM_DEAL_DETAIL_TAB`, права `crm`) и проверить сохранение на реальной сделке.
   Для первого запуска нужны права администратора портала: приложение создаёт
   поле сделки. **Это единственный этап, который снимет главный риск — см.
   «Что не проверено».**
2. **Цены в спецификации** — взять из каталога Битрикс24 по номеру позиции
   (`catalogId`, он же номер в начале имени файла картинки).
3. **Сохранение общего плана выставки** — сейчас карта выставки живёт только в
   браузере (localStorage). В сделку сохраняется лишь план отдельного стенда.
4. **Экспорт в PDF** — сейчас есть только PNG.
5. **Переход в карточку сделки** из приложения — сейчас связь односторонняя:
   приложение знает номер сделки стенда, но открыть саму карточку не может.

## Что не проверено

**Обмен данными с Битрикс24.** Код написан по документации, но до установки в
портал ни одного реального вызова не было. Локально проверено только то, что
приложение корректно определяет отсутствие портала и не падает.

Что именно выяснится при первой установке:

- создаётся ли поле сделки и находится ли потом по `XML_ID`;
- влезает ли план в поле — приложение показывает вес плана в килобайтах, но
  реальный предел поля Битрикс24 неизвестен;
- отдаёт ли портал номер сделки в том виде, который ожидает приложение.

## Требует решения

1. **Ключ amoCRM надо отозвать.** Он лежал открытым текстом в 13 файлах на
   рабочем хостинге. Считать скомпрометированным.
2. **Судьба старого функционала.** После отключения хостинга исчезнут 39 отчётов
   с выгрузкой в Excel, спецификация, паспорт стенда и генератор билетов —
   всё на PHP. Нужно решить: переписать в браузере, оставить маленький
   PHP-хостинг или сознательно отказаться.
3. **Размеры предметов** без габаритов в имени файла проставлены типовые —
   сверить с реальным каталогом.
4. **Откуда брать цены** для спецификации: каталог товаров портала, отдельный
   прайс или ручной ввод.

## Как поднять на новом компьютере

Нужен **Node.js 18+** — на нём же встанут правильные библиотеки под вашу систему.

```bash
git clone https://github.com/kukaryamba/bx24-stand-editor
cd bx24-stand-editor
npm install
npm start
```

Если `npm install` ругается на права или сеть, помогает `npm cache clean --force`.

Приложение откроется на `http://127.0.0.1:5173/`. Чтобы проверить работу с
конкретной сделкой вне портала — `http://127.0.0.1:5173/?dealId=18452`.
