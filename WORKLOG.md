не восстанавливая контекст заново. Обновляется в конце рабочего дня.

## Как устроена выкладка

`git push` → GitHub собирает приложение и кладёт готовые файлы в ветку
`deploy` → хостинг по расписанию запускает `stand-editor-pull.sh`, забирает
ветку и, если в ней новое, выкладывает. Адрес в портале не меняется.

Путь к этому был длинным, и каждое решение вынужденное:

- **Битрикс24 открывает приложение POST-запросом**, а nginx на статику
  отвечает 405. Поэтому при сборке `index.html` переименовывается в
  `index.php`: PHP принимает любой метод, кода в файле нет.
- **Портал умеет раздавать приложение из архива**, но при каждой загрузке
  меняет адрес папки, и привязка вкладки протухает с 404.
- **Cloudflare работал, но он иностранный**: при блокировках у провайдеров
  вкладка перестала бы открываться.
- **Толкать файлы с GitHub на Таймвеб по SSH нельзя**: хостинг не принимает
  SSH-подключения с серверов GitHub. Поэтому направление обратное: хостинг
  сам забирает сборку.

Выложить вручную, не дожидаясь расписания, — с рабочего компьютера:

```bash
ssh -i "$HOME/.ssh/timeweb_deploy" alitmix@vh410.timeweb.ru "sh ~/bin/stand-editor-pull.sh; tail -1 ~/stand-editor-deploy.log"
```

Копия скрипта лежит в репозитории, `deploy/timeweb-pull.sh`. Правите там —
обновите и на хостинге.

Защита хостинга (WAF) отвечает 403 на любой несуществующий `.php` и страницей
с паролем на запросы с `../` — это не ошибка приложения.

## Что сделано за 14 сентября

**Резервные копии.** Снимок собирает всё: карту выставки с анкетами, предметы
всех стендов прямо из сделок, список планов, воронку. Приёмник `backup.php`.
- Автоматически — после правок, через 20 секунд, не чаще раза в полчаса
  с одного компьютера. Хостинг хранит последние 50 и по одной в день за
  90 дней.
- Вручную — «Сделать копию сейчас», «Скачать полную копию» (с картинками
  планов, на компьютер), «Восстановить» из списка или из файла. Перед
  восстановлением текущее состояние само уходит в копию, без неё
  восстановление не начнётся.
- Всё это — на экране, который открывается из списка интеграций.
- **Проверено в портале**: копия сохранилась и видна в списке.

**Проверка входа** вынесена в `portal-auth.php`, общая для планов и копий.
Она не пропускала никого: `user.current` требует права «Пользователи», его
у приложения нет. Теперь `profile`, который прав не требует. Перед запросом
берётся свежий токен. В отказе — код ответа портала в скобках.

**Окно из списка интеграций** было обрезано снизу, потом дёргалось и уезжало.
Высота рамки считается в одном месте: во вкладке сделки с запасом под
карточку, в окне интеграций — почти во весь экран. **Проверено в портале.**

**Фриз и оклейка.** Растягиваются за ручку, надпись не растягивается.
Оклейка — янтарная, мелкий шрифт, без ограничения знаков. Обе ставятся
снаружи стенда: к сетке прижимается ближайший край панели, а не угол, —
так же для стен.

**Надпись на фризе — одна на стенд**, общая с анкетой паспорта. Правка
у панели или в анкете меняет её везде. Пустая — берётся из названия сделки
до слова «стенд». На общем плане панели подписываются каждая сама.

**Номер стенда — из названия сделки**, формат `D4-1` (буквы, число, дефис,
число; пробелы и тире приводятся). Номер из сделки главный, поле только
показывает его. Нет номера в названии — вписывается руками. Названия
запрашиваются списком по 50, при сбое — поштучно. Стенд, нарисованный из
сделки без стенда, сразу привязывается к ней как забронированный.

**Заголовок площадки и паспорта** — «Стенд D4-1 · Ромашка — 2 x 3 м».
Компания — название сделки до «стенд», без ООО, ИП, АО, ТД и кавычек,
длиннее 24 знаков обрезается. Собирается при показе хуком `useStandHeading`.
В паспорте сверху теперь только это название.

**Схема стенда** — повторное нажатие поворачивает стены на 90° по часовой.
**Проверено в портале.**

**Стенды вплотную и поверх.** Проверка наложения соседей убрана совсем —
по просьбе: контур поверх соседа — это другой стенд. Остались три вершины,
пределы плана и самопересечение. Функция `intersectsAnyStand` осталась
(касание не считает наложением) — если понадобится предупреждение.
Пока рисуют стенд, существующие стенды и предметы щелчков не ловят.

**Ещё:** сохранение плана в список видно всегда, с причиной, если нельзя;
галочка обрезки в одну строку; список «Слои» убран.

## Как поднять на новом компьютере

Нужен **Node.js 18+**. На машине его может не быть вовсе — ставится через
`winget install OpenJS.NodeJS.LTS`.

```bash
git clone https://github.com/kukaryamba/bx24-stand-editor
cd bx24-stand-editor
npm install
npm start
```

Откроется `http://127.0.0.1:5173/`. Проверить с конкретной сделкой вне портала —
`http://127.0.0.1:5173/?dealId=18452`.

Сборка — `npm run build`, она же единственная проверка кода: тестов и линтера
нет. Для SSH к хостингу нужен ключ `timeweb_deploy`: на другом компьютере его
нет, там выкладка идёт только через расписание.
