# Ход работы

Файл для того, чтобы продолжить работу на другом компьютере или в новой сессии,
не восстанавливая контекст заново.

## Задача

Приложение для планирования выставочных стендов работало в amoCRM. Нужно
перенести его в Битрикс24.

## Исходное состояние: три папки

Их передала коллега, все три остались на рабочем компьютере и **в репозиторий не
попали** — в них лежат ключи и логи с данными клиентов.

| Папка | Что это |
|---|---|
| `amo_crm` | React-редактор общего плана + копия старого PHP-приложения. Делался через Codex |
| `amo_crm 2` | то же старое приложение + начатый слой перехода на Битрикс24, другая нейросеть |
| `оригинал amo_crm старый` | оригинал с хостинга, без изменений |

Проверено: **фронтенд второй и третьей папок побайтово идентичен**. Реальных
версий продукта две — старая на PHP и новая на React.

## Почему старое приложение не вернуть

1. **API amoCRM не отвечает.** Запрос к `/private/api/v2/` возвращает 402 — и с
   ключом, и без него. Приложение построено на устаревшем API с авторизацией по
   логину и хэшу.
2. **Библиотека ломает ответы.** На PHP 8 `amocrm.phar` выдаёт полтора десятка
   сообщений `Deprecated` перед JSON, из-за чего браузер не может его разобрать.
3. **Хостинг отключают** — компания переезжает на Тильду. Всё, что на PHP,
   перестанет работать физически.

## Что решили

Делать новое приложение на React в папке `bx24_stand_editor` (этот репозиторий),
на основе редактора из папки `amo_crm`. Работать поэтапно.

## Сделанные этапы

1. **Запуск.** Библиотеки в исходной папке были собраны под macOS — Vite не
   стартовал на Windows. Докачаны сборки `@rollup/rollup-win32-x64-msvc` и
   `@esbuild/win32-x64`.
2. **Разбор.** Сведено, что из ТЗ уже есть в старом приложении и в React-редакторе.
3. **План стенда.** Добавлен второй экран: каталог 43 предметов, расстановка
   перетаскиванием, поворот, удаление, панель свойств.
4. **Сохранение в сделку.** Панель «Сделка», запись плана в пользовательское поле
   через JS-библиотеку Битрикс24, без своего сервера.

## Что дальше

Выбрать следующий шаг:

- **Спецификация со стоимостью** — таблица предметов на плане с количеством и
  суммой, как в старом `specification.php`. Цены живут в каталоге портала.
- **Установка в портал** — собрать `dist`, выложить, зарегистрировать локальное
  приложение и проверить сохранение на реальной сделке.
- **Экспорт в PNG и PDF** — план для клиента и для монтажников.
- **Разделение экранов** — сейчас оба экрана рисуют один и тот же план; нужно
  разделить карту павильона и отдельный стенд со своими размерами.

## Что не проверено

**Обмен данными с Битрикс24.** Код написан по документации, но до установки в
портал ни одного реального вызова не было. Локально проверено только то, что
приложение корректно определяет отсутствие портала и не падает.

## Требует решения

1. **Ключ amoCRM надо отозвать.** Он лежал открытым текстом в 13 файлах на
   рабочем хостинге. Считать скомпрометированным.
2. **Судьба старого функционала.** После отключения хостинга исчезнут 39 отчётов
   с выгрузкой в Excel, спецификация, паспорт стенда и генератор билетов —
   всё на PHP. Нужно решить: переписать в браузере, оставить маленький
   PHP-хостинг или сознательно отказаться.
3. **Размеры предметов** без габаритов в имени файла проставлены типовые —
   сверить с реальным каталогом.

## Как поднять на новом компьютере

Нужен **Node.js 18+** — на нём же встанут правильные библиотеки под вашу систему.

```bash
git clone <адрес репозитория>
cd bx24_stand_editor
npm install
npm start
```

Если `npm install` ругается на права или сеть, помогает `npm cache clean --force`.
