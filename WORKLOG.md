Файл для того, чтобы продолжить работу на другом компьютере или в новой сессии,
не восстанавливая контекст заново. Обновляется в конце рабочего дня.

Обновлено 11 сентября 2026 года, конец недели. Коммит `0b543c2`.

**Незаконченного в рабочей копии нет.** Всё закоммичено, отправлено и выложено

## Задача

Приложение для планирования выставочных стендов работало в amoCRM. Нужно
перенести его в Битрикс24.

## Как устроена выкладка

`git push` → GitHub собирает приложение и кладёт готовые файлы в ветку
`deploy` → хостинг по расписанию запускает `stand-editor-pull.sh`, забирает
ветку и, если в ней новое, выкладывает. Адрес в портале не меняется.

Путь к этому был длинным, и каждое решение вынужденное:

- **Битрикс24 открывает приложение POST-запросом**, а nginx на статику
  отвечает 405. Поэтому при сборке `index.html` переименовывается в
  `index.php`: PHP принимает любой метод, кода в файле нет.
- **Портал умеет раздавать приложение из архива**, но при каждой загрузке
  меняет адрес папки, и привязка вкладки протухает с 404.
- **Cloudflare работал, но он иностранный**: при блокировках у провайдеров
  вкладка перестала бы открываться.
- **Толкать файлы с GitHub на Таймвеб по SSH нельзя**: хостинг не принимает
  SSH-подключения с серверов GitHub — по IPv4 таймаут, по IPv6 «Network is
  unreachable». Иногда проходило, отсюда долгая путаница. Поэтому
  направление обратное: хостинг сам забирает сборку, исходящие соединения
  с него работают.

Выложить вручную, не дожидаясь расписания, — с рабочего компьютера:

```bash
ssh -i "$HOME/.ssh/timeweb_deploy" alitmix@vh410.timeweb.ru "sh ~/bin/stand-editor-pull.sh; tail -1 ~/stand-editor-deploy.log"
```

Копия скрипта лежит в репозитории, `deploy/timeweb-pull.sh`. Правите там —
обновите и на хостинге.

**Подробный лог выкладки на GitHub видит только администратор репозитория.**
Если выкладка упадёт, текст ошибки выносится в аннотацию шага — они видны
публично. Без входа у API лимит 60 запросов в час, частый опрос его выедает.

## Ждёт действий пользователя

1. **Сменить адрес в настройках локального приложения** в портале на
   `https://alitinform.ru/stand-editor/`, в обоих полях. **Редактировать
   существующее приложение, не создавать новое**: карта выставки, выбор
   воронки и список планов хранятся в настройках именно этого приложения.
   Приложение само заметит смену адреса и перепривяжет вкладку.
2. **Добавить расписание** в панели Таймвеба, Планировщик задач: команда
   `sh /home/a/alitmix/bin/stand-editor-pull.sh`, каждые 5 минут. Пока его
   нет, выкладывать приходится вручную после каждого пуша.
3. Необязательно: удалить четыре секрета SSH в настройках репозитория —
   выкладка по SSH убрана, они не используются.

## Что сделано

**Два экрана.** Общий план выставки и площадка стенда. У каждого стенда своя
площадка, заводится при первом открытии, размеры берутся с контура на карте.
Вкладка в сделке сразу открывает площадку стенда этой сделки.

**Сетка и загрузка плана.** При загрузке картинка обрезается по сетке
чертежа — шапка, текст и поля убираются, край ложится на узел. Отключается
галочкой. Шаг сетки: грубо — автокорреляцией, из кандидатов (половинный,
двойной и прочие) выбирается тот, у которого на линии темно, а посередине
клетки светло; затем спектральное уточнение по обеим осям. Проверено на
настоящих файлах: полный план ЦБСС с шапкой — 27,72 при известных 27,69.
Прежний алгоритм на планах ЦБСС давал полшага — ошибка была в работе,
пока подложку ставили кнопкой готового плана, её не замечали.

Расчёт отделён от браузера в `detectGridFromPixels` — его можно прогнать
на картинках из Node.

**Планы выставок.** Загруженный план отправляется на хостинг приёмником
`upload.php`, в карту выставки уходит только ссылка — коллеги видят подложку.
Приёмник принимает файл только от сотрудника портала: токен сверяется
запросом к Битрикс24, и только для порталов из списка. Проверяется
содержимое файла, имя придумывает сервер. Планы можно сохранять в общий
список рядом с готовым ЦБСС 2026 — список хранится в настройках приложения
на портале. Замена подложки и удаление из списка требуют второго щелчка.

**Каталог.** 59 позиций по форме заказа оборудования ЦБСС 2026, плюс
фризовая панель. Артикулы проставлены только там, где они есть в прайсе.
Обозначения нарисованы заново. **Генератор каталога удалён вместе с
временной папкой сессии** — фризовая панель добавлена вручную, и так
придётся делать дальше, либо написать генератор заново.

Старый каталог из 44 позиций — второй вкладкой: на нарисованных планах
стоят его предметы.

**Спецификация и паспорт стенда.** Паспорт повторяет состав старого
`pasport_generator`, печатается на листах A4. Анкета паспорта — фриз, цвета,
самозастройка, диплом, тяжёлая техника — заполняется справа на площадке
стенда и хранится в самом стенде. С полями сделки она сознательно не связана.
Фриз и стены считаются в спецификации раздельно, погонными метрами.

**Битрикс24.** Приложение встраивается вкладкой в карточку сделки, место
встраивания регистрирует само. Права: **CRM** и **Встраивания**. Из карточки
стенда можно открыть его сделку в новой вкладке.

**Хранение.** Карта выставки — в настройках приложения на портале. План
стенда — в поле его сделки, подтягивается при открытии площадки. Подложки
планов — на хостинге. В браузере ничего важного не остаётся.

**Ограничение по воронке.** Вкладка появляется во всех сделках — Битрикс24
не умеет иначе. В чужой воронке приложение показывает заглушку.

**Работа с холстом.** Множественное выделение: Ctrl+клик, рамка, Delete
удаляет всё одним шагом. Мебель ставится свободно, стены и фриз цепляются
к сетке. Ширина боковых панелей тянется мышью. Ctrl+Z и Ctrl+Y. Кнопка
«Сохранить JSON» убрана — дублировала автосохранение. Инструмент рисования
стенда называется «Создать стенд».

## Что не проверено

- **Загрузка плана на хостинг с настоящим токеном.** Проверены только отказы:
  без входа, с чужим порталом, с поддельным токеном — все дают 403 от кода
  приёмника. Успешная загрузка возможна только из портала.
- Список планов и открытие сделки — только сборка, не в портале.
- Файл `Telegram Desktop\план.jpg` (пустой зал) нарисован в двух масштабах:
  левая часть 27,82, правая 28,5–28,6. Одна сетка на обе не ляжет. Это свойство
  файла, не приложения.
- Предел размера настроек приложения неизвестен: карта выставки растёт
  вместе с числом стендов.
- Одновременное редактирование: побеждает сохранивший последним.

## Как поднять на новом компьютере

Нужен **Node.js 18+**. На машине его может не быть вовсе — ставится через
`winget install OpenJS.NodeJS.LTS`.

```bash
git clone https://github.com/kukaryamba/bx24-stand-editor
cd bx24-stand-editor
npm install
npm start
```

Откроется `http://127.0.0.1:5173/`. Проверить с конкретной сделкой вне портала —
`http://127.0.0.1:5173/?dealId=18452`.

Сборка — `npm run build`, она же единственная проверка кода: тестов и линтера
нет. Для SSH к хостингу нужен ключ `timeweb_deploy`: на другом компьютере его
нет, там выкладка идёт только через расписание.
