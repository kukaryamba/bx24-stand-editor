Файл для того, чтобы продолжить работу на другом компьютере или в новой сессии,
не восстанавливая контекст заново. Обновляется в конце рабочего дня.

Обновлено 13 августа 2026 года, вечер. Коммит `f0ff279`.

## Задача

Приложение для планирования выставочных стендов работало в amoCRM. Нужно
перенести его в Битрикс24.

| Старое PHP-приложение | `C:\Веб приложение стенды`, три папки, в репозиторий не попали: там ключи и данные клиентов |

Каталог, описанный в CLAUDE.md, — это старый снимок. Актуальная работа идёт
в каталоге с суффиксом `-git`.

## Как устроена выкладка

`git push` → Cloudflare пересобирает Worker → адрес в портале не меняется.
Никаких архивов и перезаливок.

Так вышло не сразу. Битрикс24 открывает встроенное приложение POST-запросом,
а статика на POST отвечает 405 — проверено и на GitHub Pages, и на nginx.
Поэтому в `worker/index.js` перехват: POST отдаётся как GET. На хостинге с PHP
той же цели служило бы переименование `index.html` в `index.php`.

Портал умеет раздавать приложение сам, из загруженного архива, — но при каждой
загрузке он меняет адрес папки, и привязка вкладки протухает с 404. Поэтому
выбран постоянный адрес.

## Что сделано

**Два экрана.** Общий план выставки и площадка стенда. У каждого стенда своя
площадка, заводится при первом открытии, размеры берутся с контура на карте.

**Сетка.** Масштаб и сдвиг определяются автоматически по сетке чертежа:
автокорреляция находит период, метод наименьших квадратов уточняет шаг, фаза
считается круговым средним. Для ЦБСС 2026 — 27,69 пикселя на метр. Рядом поля
ручной подстройки.

**Каталог.** 59 позиций по форме заказа оборудования ЦБСС 2026, с артикулами
прайса. Обозначения нарисованы заново, генератор собирает их и файл каталога
из одного описания (`scratchpad/catalog`). Старый каталог из 44 позиций остался
второй вкладкой: на нарисованных планах стоят его предметы.

**Спецификация и паспорт стенда.** Паспорт повторяет состав старого
`pasport_generator`: компания и контакт из сделки, площадь, план стенда
картинкой, список оборудования с обозначениями, примечание.

**Битрикс24.** Приложение статичное, встраивается вкладкой в карточку сделки.
Место встраивания регистрирует само при открытии из списка интеграций
(`placement.bind`), потому что в форме локального приложения его не выбрать.
Права нужны два: **CRM** и **Встраивания**.

**Хранение.** Карта выставки — в настройках приложения на портале, общая для
всех. План отдельного стенда — в поле его сделки, подтягивается при открытии
площадки и уезжает обратно через две секунды. В браузере не хранится ничего
важного, кроме загруженной вручную подложки.

**Ограничение по воронке.** Вкладка появляется во всех сделках — Битрикс24
не умеет иначе. В чужой воронке приложение показывает заглушку. Воронка
выбирается на экране установки.

## Как поднять на новом компьютере

Нужен **Node.js 18+**. На машине его может не быть вовсе — ставится через
`winget install OpenJS.NodeJS.LTS`.

```bash
git clone https://github.com/kukaryamba/bx24-stand-editor
cd bx24-stand-editor
npm install
npm start
```

Откроется `http://127.0.0.1:5173/`. Проверить с конкретной сделкой вне портала —
`http://127.0.0.1:5173/?dealId=18452`.

Сборка — `npm run build`, она же единственная проверка кода: тестов и линтера
нет.
