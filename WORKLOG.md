# Ход работы

Файл для того, чтобы продолжить работу на другом компьютере или в новой сессии,
не восстанавливая контекст заново. Обновляется в конце рабочего дня.

Обновлено 15 сентября 2026 года, конец дня. Последний коммит с кодом `c227743`.

**Незаконченного в рабочей копии нет.** Всё закоммичено, отправлено и выложено
на хостинг. Портал открывает приложение с Таймвеба, расписание выкладки
работает.

**Утром — две открытые жалобы пользователя** (см. «Что дальше», пункт 1):
приложение не всегда загружается; новое оборудование без картинок.

**После каждой выкладки приложение в портале надо открыть заново**: уже
открытая карточка сделки держит старую версию. Прежде чем искать ошибку,
сверить хеш `assets/index-*.js` на https://alitinform.ru/stand-editor/
(POST-запросом) с последней сборкой.

## Задача

Приложение для планирования выставочных стендов работало в amoCRM. Нужно
перенести его в Битрикс24.

## Как устроена выкладка

`git push` → GitHub собирает приложение и кладёт готовые файлы в ветку
`deploy` → хостинг по расписанию запускает `stand-editor-pull.sh`, забирает
ветку и, если в ней новое, выкладывает. Адрес в портале не меняется.

- **Битрикс24 открывает приложение POST-запросом** — поэтому `index.html`
  при сборке переименовывается в `index.php`.
- **Толкать файлы с GitHub на Таймвеб по SSH нельзя** — хостинг сам забирает сборку.
- **Хостинг кэширует статику на год** (`Cache-Control: max-age=31536000`).
  К адресам картинок каталога добавляется метка сборки `?v=` (`__BUILD_STAMP__`
  в `vite.config.ts`), иначе перерисованный значок не виден.

Выложить вручную, не дожидаясь расписания, — с рабочего компьютера:

```bash
ssh -i "$HOME/.ssh/timeweb_deploy" alitmix@vh410.timeweb.ru "sh ~/bin/stand-editor-pull.sh; tail -1 ~/stand-editor-deploy.log"
```

Копия скрипта лежит в репозитории, `deploy/timeweb-pull.sh`.

Защита хостинга (WAF) отвечает 403 на любой несуществующий `.php` и страницей
с паролем на запросы с `../` — это не ошибка приложения.

**Сообщения коммитов с кавычками** в PowerShell ломают аргументы git —
писать сообщение в файл инструментом записи и `git commit -F файл`.
`Set-Content -Encoding UTF8` добавляет BOM в начало сообщения.

**Диагностика в портале.** Через Claude in Chrome на странице портала доступен
`BX.rest.callMethod` от имени пользователя — так читали `UF_CRM_STAND_PLAN`
сделки. Только чтение и только с разрешения пользователя.

## Что сделано за 15 сентября

**Базовая комплектация «Стандарт»** (`shared/domain/standBase.ts`) — таблица
прайса по площади: стол 70x70, стулья, споты, розетки, вешалка, корзина,
комната переговоров (стены, дверь, занавеска). Расстановка как на схеме
прайса, комната — в правом заднем углу, второй стол в ней. Проверено
расчётом на 7 размерах. Ставится при создании площадки и **сама, если
площадка и план в сделке пусты**; кнопка «Расставить базу «Стандарт»»
заменяет всё базой. **Больше 20 м² — только стены и фриз**, мебель по счёту.
Ковёр по умолчанию **серый** (пустое поле анкеты = серый), площадка
закрашивается цветом из анкеты.

**Три ошибки обмена планом со сделкой, из-за которых база мелькала и пропадала:**
- пустой план из сделки стирал базу — теперь не стирает;
- чтение из сделки шло до прихода карты из портала — теперь после (`portalSettled`);
- **главная**: в сделке 80930 лежали предметы со слоем площадки другого стенда
  (сделку перевязывали), они заменяли базу и не рисовались. Теперь при загрузке
  слой перепривязывается, а объект с неизвестным слоем рисуется.

**Номер и название стенда.** Номер из сделки понимает пробел «D 4-2», русские
буквы-двойники приводятся к латинице («Е 3-1» → E3-1). Название —
«Стенд D4-2 · ПКБ Техноприбор — 6 м²» (площадь вместо габаритов), одно для
заголовка, левой панели и паспорта. Названия компаний — на стендах общего
плана; стенды на плане непрозрачные.

**Надпись на фризе** — название компании без ООО/АО/кавычек/«стенд»/номера
(`companyName`), в поле сразу текстом, правится; тронутая хранится в анкете,
даже пустая; «Взять из сделки» возвращает.

**Загрузка счетов PDF** (`shared/invoice/`, `InvoiceImportDialog`). pdf.js
в браузере, строки по координатам, таблица «Товары (работы, услуги)», словарь
названий по 5 настоящим счетам (ВСЕЛУГ, ТФК Машинери, КМЗ). Неоднозначное
(«стул», «барный стул», круглый стол без размера) — выбор человека,
запоминается в `stand_editor_invoice_mappings`. Сбор, площадь, печать, отели —
пропуск с причиной. Предметы встают под площадкой, выделенными. Схему стенда
из счёта **не предлагать** — по просьбе. Выбор каталога — по разделам.
Проверено: разбор 5 счетов в Node; worker pdf.js запускается с хостинга.

**Редактор:** перетаскивание выделенной группы одним шагом; вид открытия
общего плана («Открывать план так, как сейчас на экране», в плане `startView`);
поиск в палитре по артикулу и названию; светильники рисуются поверх стен.

**Обозначения:** глухие стены — сплошная чёрная полоса; раздвижная дверь —
чёрный зигзаг; корзина — круг с сеткой 3x3; вешалка — грабля; плазма —
контур с TV. Вешалка, корзина, плазма — без белой рамки.

**Каталог:** стол-подиум 205; круглый стол D-0,8 м 625a; 203 переименован
в «Стойка информационная с внутренней полкой 1 x 0,5 м, h=1 м»; у архивного
шкафа 220 — высота.

**Паспорт:** колонки № (узкая), наименование, артикул, количество, обозначение;
периметр убран отовсюду. Ширины колонок — по классам, не по порядку
(по порядку номер занял 58%).

**Убрано:** кнопки «Сохранить в сделку»/«Загрузить из сделки» (панель «Сделка»
показывает номер и ошибку автосохранения); надпись «JSON синхронизирован».
Готовый план ЦБСС 2026 можно скрыть из списка (`stand_editor_hidden_plans`).

**Печать паспорта в отдельной вкладке сделана и отменена** по просьбе
(`84fb1d6` → `c227743`). Причина жалобы «КМЗ — паспорт не сохраняется в PDF»
не найдена: печать сейчас по-старому, `window.print()` из рамки портала.

## Как поднять на новом компьютере

Нужен **Node.js 18+** — `winget install OpenJS.NodeJS.LTS`.

```bash
git clone https://github.com/kukaryamba/bx24-stand-editor
cd bx24-stand-editor
npm install
npm start
```

Откроется `http://127.0.0.1:5173/`. С конкретной сделкой вне портала —
`http://127.0.0.1:5173/?dealId=18452`.

Сборка — `npm run build`, она же единственная проверка кода: тестов и линтера
нет. Для SSH к хостингу нужен ключ `timeweb_deploy`: на другом компьютере его
нет, там выкладка идёт только через расписание.
