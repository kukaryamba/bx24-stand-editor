# Редактор планов выставочных стендов для Битрикс24

Приложение встраивается в карточку сделки Битрикс24 и позволяет нарисовать план
выставки и расставить оборудование на стенде.

Заменяет старое приложение на PHP, которое работало с amoCRM.

## Запуск

Нужен Node.js 18 или новее.

```bash
npm install
npm start
```

Откроется `http://127.0.0.1:5173/`.

Чтобы проверить работу с конкретной сделкой вне портала:

```text
http://127.0.0.1:5173/?dealId=18452
```

Сборка для выкладки:

```bash
npm run build
```

Готовые файлы появятся в папке `dist` — её содержимое и выкладывается на хостинг.

## Что уже работает

- **Общий план выставки** — стенды рисуются полигонами по сетке, привязка вершин
  к узлам, проверка самопересечений и наложений, автоматический расчёт площади.
- **План стенда** — палитра из 43 предметов по 8 категориям, расстановка
  перетаскиванием с прилипанием к сетке, поворот на 90°, удаление.
- **Своя площадка у каждого стенда** — заводится при первом открытии, размеры
  берутся с контура, нарисованного на карте выставки. Между стендами можно
  переходить списком, не возвращаясь на общий план.
- **Типовые схемы и размеры стендов** — линейный, угловой, полуостров, остров;
  схема расставляет стены по периметру, мебель остаётся на месте.
- **Спецификация** — перечень предметов по категориям, площадь, периметр и длина
  стеновых панелей, выгрузка текстом и печать.
- **Экспорт в PNG** — план целиком, а не видимая часть.
- Слои, отмена и повтор действий, масштабирование, панорама колёсиком мыши.
- Сохранение в браузере (localStorage) — работает без Битрикс24.
- **Сохранение плана стенда в сделку** — панель «Сделка» на экране плана стенда.

## Чего ещё нет

- Стоимость в спецификации: цены лежат в каталоге портала и пока не подключены.
- Экспорт в PDF — есть только PNG.
- Сохранение общего плана выставки в CRM — сохраняется только план стенда.
- Переход из приложения в карточку сделки.

## Как устроена связь с Битрикс24

Приложение работает **без собственного сервера**: оно общается с порталом напрямую
из браузера через JS-библиотеку Битрикс24. Поэтому подойдёт любой статический
хостинг с HTTPS — GitHub Pages, Cloudflare Pages, Netlify.

Схема повторяет логику старого приложения:

```
Общий план выставки
   │  стенд привязан к сделке
   ▼
Карточка сделки в Битрикс24
   │  в ней открыт этот виджет
   ▼
План конкретного стенда
```

План стенда хранится в пользовательском поле сделки в виде JSON. Поле приложение
**создаёт само** при первом сохранении (`crm.deal.userfield.add`), поэтому для
первого запуска нужны права администратора портала. Ищет оно своё поле по
служебному признаку `XML_ID = BX24_EXPO_STAND_PLAN`, а не по имени — Битрикс24
часто выдаёт полям имена вида `UF_CRM_1712345678`.

## Установка в портал

1. Настройки → Разработчикам → Другое → Локальное приложение.
2. Адрес приложения: ссылка на выложенную папку `dist`.
3. Встраивание: `CRM_DEAL_DETAIL_TAB` — вкладка в карточке сделки.
4. Права: `crm`.

## Структура

```text
src/app                     — оболочка приложения
src/features/plan-editor
  components                — холст, палитра предметов, панели
  store                     — состояние редактора (zustand)
src/shared
  crm                       — работа с Битрикс24
  domain                    — модель данных и каталог предметов
  geometry                  — расчёты по полигонам
  storage                   — сохранение в браузере
public/furniture            — 43 картинки предметов
```

## Откуда взялся каталог предметов

Картинки и размеры перенесены из старого приложения. Размеры зашиты в именах
файлов: `311_stol_0,7_h_1,2m` — стол 0,7 x 1,2 м. Номер в начале имени — это
идентификатор позиции в каталоге CRM, по нему потом будет считаться спецификация.

Там, где размера в имени не было (стулья, светильники), проставлены типовые
габариты — **их стоит сверить с реальным каталогом**.
